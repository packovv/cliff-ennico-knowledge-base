# Таксономия и поля каталога

Ключи служат фильтрами поиска, а не подтверждёнными тезисами автора. Генератор проверяет ключи, но не перезаписывает этот файл. Изменение набора ключей требует согласованного изменения констант в `build_kb.py`.

## Темы

| Ключ | Включать | Не подменять этой темой |
|---|---|---|
| `clients` | Выбор клиентов, отношения и обслуживание | Любое упоминание покупателя в примере |
| `contracts` | Условия соглашений, распределение обязательств и переговоры о них | Общие знакомства или подбор партнёров |
| `payments` | Счета, получение оплаты, просроченные долги | Финансирование компании или реорганизацию должника |
| `sales` | Продажа продукта, услуги, презентация предложения | Только привлечение внимания без предложения |
| `pricing` | Установление цены и её обоснование | Налоговые ставки и стоимость кредита |
| `partnerships` | Выбор соучредителей, советников и управленческой команды | Спор между партнёрами без отдельного основания |
| `business_formation` | Подготовка запуска и создание бизнеса | Слово entrepreneur само по себе |
| `intellectual_property` | Авторские права, патенты, товарные знаки и коммерческие секреты | Любой творческий бизнес без обсуждения прав |
| `employment` | Найм, отношения с работниками и рынок труда | Выбор соучредителей |
| `taxes` | Налоговые обязательства и процедуры | Любое бюджетирование |
| `disputes` | Конфликт требований и его разрешение | Профилактику рисков без конфликта |
| `risk_management` | Предупреждение потерь, мошенничества и правовых рисков | Все бизнес-решения без конкретного риска |
| `marketing` | Поиск аудитории, каналы, позиционирование и конкуренцию | Только согласование цены сделки |
| `operations` | Организацию ежедневной работы и времени | Универсальный запасной тег, подтверждающий содержание; автоматически это лишь маршрут для неизвестной темы |
| `financing` | Привлечение капитала, финансовое планирование, краудфандинг и реорганизацию | Взыскание обычного клиентского счёта |

## Ситуации

| Ключ | Основание и граница |
|---|---|
| `client_nonpayment` | Просрочка оплаты клиентом; банкротство компании само по себе недостаточно |
| `scope_creep` | Рост объёма работ без согласованного изменения условий; не любые переговоры |
| `client_dispute` | Конкретное разногласие с клиентом; не управление клиентами вообще |
| `refund_request` | Требование вернуть оплату; не любая задолженность |
| `partner_dispute` | Конфликт партнёров; не их подбор и не создание команды |
| `business_startup` | Запуск бизнеса; не любая аудитория предпринимателей |
| `contract_negotiation` | Согласование условий сделки или соглашения; не любые коммуникации |
| `ip_infringement` | Предполагаемое нарушение интеллектуальных прав; не обзор этих прав |
| `employee_issue` | Конкретная проблема с работником; не обзор рынка труда |
| `tax_issue` | Налоговый вопрос; не финансовый бюджет |
| `lawsuit_threat` | Конкретная угроза иска; не общий обзор защиты от рисков |
| `business_sale` | Продажа самой компании; не продажа бизнес-плана инвестору |

## Организации и стадии

`small_business` обозначает малый бизнес, `consulting_business` консультационную практику, `creative_business` творческую деятельность, `ecommerce_business` интернет-торговлю, `nonprofit` некоммерческую организацию. Дополнительные ключи требуют соответствующего предмета источника, а не случайного примера.

`startup` означает обсуждение запуска, `operating` работу действующей компании, `unknown` отсутствие достаточных оснований выбрать стадию. Генератор не назначает operating всем прочим записям.

## Применимость и право

`rf_applicability`:

- `unknown`: применимость не установлена; значение по умолчанию.
- `direct_business`: вручную проверенная бизнес-практика без выявленного переноса правового механизма; не гарантия результата.
- `concept_only`: можно изучать общую логику, но механизмы нуждаются в локализации.
- `requires_rf_legal_review`: есть повод отдельно проверить применимое право РФ перед практическим использованием; автоматический сигнал не является юридическим заключением.
- `not_applicable`: при ручном разборе установлено несоответствие целевому контексту.

`us_law_dependency`:

- `unknown`: зависимость не оценена, в том числе при отсутствии совпадений словаря.
- `none`: только после содержательной проверки, а не по отсутствию слова law.
- `low`: правовой контекст вторичен; ручная оценка.
- `medium`: правовой контекст существенно влияет на рекомендацию; ручная оценка.
- `high`: автоматический предупредительный флаг при явном американском сигнале либо ручная оценка зависимости от механизмов США. Сам флаг не доказывает зависимость всех тезисов записи.

`legal_signal` хранит результат буквального поиска в полном тексте: `not_detected`, `possible_legal` или `us_specific`. В `legal_evidence` записан короткий точный фрагмент первого выбранного совпадения с контекстом; это не пересказ и не юридическая квалификация. Словарь неполон, возможны ложные срабатывания и пропуски.

## Достоверность и обслуживание

- `classification_method`: `title_heuristic` для предварительных тегов по имени файла; `manual_review` только после содержательного разбора человеком.
- `confidence`: `low`, `medium`, `high`. Автоматическая классификация всегда low; юридические слова не повышают уверенность.
- `source_status`: `active` для существующего пути, `archived` для исчезнувшего. Архивная строка сохраняет ID. Переименование автоматически считается новым путём плюс архивом; сходство текста и дубликаты не доказывают идентичность.
- `notes_status`: `indexed` без содержательного ревью, `reviewed` при сохранённом ручном ревью и прежнем хеше, `stale` при изменении источника после ручного ревью. Устаревшие теги заменяются предварительными, дата прежнего ревью остаётся исторической.
- `metadata_status`: `unknown`, `candidate`, `confirmed`; переносится из авторитетной таблицы `source-metadata.csv`.
- `indexed_at` обозначает время индексирования UTC, не дату выступления. `last_reviewed_at` пуст для непроверенных записей; старая дата технической индексации не считается ревью.
- `source_sha256` и `source_bytes` фиксируют точные байты источника. `manifest_id` связывает активную строку с текущим снимком. У архивной строки остаётся последний манифест её присутствия.
- `published_at` и `url` заполняются в каталоге только для confirmed. Пустые поля unknown означают честно неизвестные данные, а не незавершённые заглушки проверенных данных.
- `summary` описывает метод автоматической обработки и название, а не выдаёт результат за прочитанное смысловое резюме. `concepts` автоматически не сочиняется.

Не более пяти тем и пяти ситуаций, только канонические ключи через `;`. Отсутствующий тег не доказывает отсутствие темы. Предварительные теги помогают выбрать текст для чтения, но не заменяют его.

## Метаданные источников

Таблица `source-metadata.csv` редактируется человеком и не генерируется заново при каждом запуске. Поля `file`, `url`, `published_at`, `status`, `evidence`, необязательное `notes`. Новые пути получают unknown; старые строки, включая архивные и дополнительные столбцы, сохраняются.

Для unknown оставляйте URL, дату и evidence пустыми. Для candidate допустима проверенная синтаксически ссылка-кандидат, но её нельзя цитировать как оригинал. Для confirmed обязательны HTTP(S) URL, дата YYYY-MM-DD и непустое описание доказательства совпадения конкретной записи и подтверждения даты. Например, отметьте сравнение начала и характерного фрагмента расшифровки с записью и место публикационной даты. Генератор проверяет формат и наличие evidence, но не проверяет истинность человеческого подтверждения или доступность ссылки.

Главная страница автора https://succeedinginyourbusiness.com/ связывает автора с каналом `UCahNH8FgCHT0fFt0cONZj0A` и видео https://www.youtube.com/watch?v=mNe7hUAkx4M. По переданному публичному исследованию вступление этого видео совпадает с `019`, поэтому статус confirmed подтверждает идентичность записи, но не точность всей расшифровки. Остальные 52 записи имеют candidate по совпадению названия и channel_id без сравнения вступления. Доказательства и пределы проверки сохранены в `source-research.md`.

`published_at` хранит дату публикации видео из индивидуального YouTube upload_date, не дату записи выступления. Для кандидата это дата только найденного видео, пока не доказано, что TXT относится именно к нему. Даты записи всех выступлений остаются неизвестными. Не назначайте их по файловой системе, теме пандемии, публикационной дате или времени индексирования. Генератор не выполняет сетевую проверку и не повышает candidate до confirmed.
